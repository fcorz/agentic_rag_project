# Agentic RAG 知识库项目计划

## 项目定位

本项目计划从后端工程视角出发，手动开发一个可用于技术分享和项目经验展示的 Agentic RAG 知识库系统。

项目重点不是做一个简单的聊天页面，也不是二次开发现有 Vanna 项目，而是完整展示后端工程师在 AI 应用中的核心能力：

- 文档接入与解析
- 语义分块
- Embedding 与向量检索
- 关键词检索与混合召回
- 查询理解与查询改写
- Rerank 与上下文构建
- Agent 工作流编排
- 工具调用
- 评测与可观测性
- 权限、安全、部署和工程闭环

最终项目目标：

```text
构建一个面向企业知识库场景的 Agentic RAG 后端工程项目，
用于展示从基础 RAG 到进阶 Agent 工程的完整技术链路。
```

## 语言选择原则

本项目从后端视角出发，候选技术语言包括：

- Python
- Go
- PHP

但这并不表示三个语言都必须使用。语言选择应基于模块职责，而不是为了堆技术栈而强行引入。

推荐原则：

| 场景 | 推荐语言 | 原因 |
|---|---|---|
| LLM 调用、RAG 编排、Embedding、Rerank、Agent Workflow | Python | AI 生态最完整，适合快速实现和实验 |
| API Gateway、SSE 流式响应、高并发工具服务、任务调度 | Go | 性能稳定，适合服务化和高并发 |
| 传统业务系统集成、管理后台 API、企业现有 PHP 生态接入 | PHP | 适合模拟存量企业系统和后台集成 |

第一版建议优先使用：

```text
Python + PostgreSQL + pgvector + Redis + Docker Compose
```

当项目进入服务化和工程展示阶段，再按需要引入 Go。PHP 仅在需要模拟传统业务系统接入时使用。

## 技术栈规划

| 技术领域 | 核心技术 | 解决的问题 |
|---|---|---|
| 模型调用 | OpenAI-compatible API / Structured Output / Prompt Template | 模型调用稳定、输出可控 |
| 文档解析 | PDF / DOCX / Markdown / TXT Parser | 将非结构化资料转成文本 |
| 分块策略 | Semantic Chunking / Parent-child Chunk / Metadata-aware Chunking | 避免简单切片导致上下文断裂 |
| 向量检索 | PostgreSQL + pgvector | 保存 embedding 并做语义召回 |
| 关键词检索 | PostgreSQL FTS / BM25 思路 | 补足向量检索对精确词不敏感的问题 |
| 混合检索 | Vector + Keyword + Metadata Filter | 提升召回准确率 |
| 查询理解 | Query Rewrite / Intent Detection / Structured Planning | 让系统先理解问题再检索 |
| Rerank | Cross Encoder / LLM Rerank / 轻量 Reranker | 降低无效上下文，减少 token 消耗 |
| Agent 编排 | LangGraph 或自研状态机 | 支持规划、检索、验证、回答多阶段流程 |
| 工具调用 | Tool Calling / Tool Registry / MCP-like Contract | 标准化连接外部工具 |
| 评测体系 | Golden Set / RAGAS 思路 / 自研 Evals | 量化 RAG 效果 |
| 可观测性 | OpenTelemetry / Trace Log / Prompt Log | 追踪每次请求的完整链路 |
| 安全 | 权限过滤 / Prompt Injection 防护 / PII Masking | 防止越权、污染和敏感信息泄露 |
| 工程交付 | Docker Compose / Migration / CI / Makefile | 可部署、可复现、可演示 |

## 核心流程

### 文档入库流程

```text
上传文档
  -> 创建 Document 记录
  -> 异步解析文本
  -> 语义分块
  -> 生成 embedding
  -> 写入 PostgreSQL + pgvector
  -> 建立 FTS 关键词索引
  -> 记录处理状态
```

### 问答流程

```text
用户问题
  -> Query Understanding
  -> Query Rewrite
  -> Hybrid Retrieval
  -> Rerank
  -> Context Builder
  -> Answer Agent
  -> Citation Builder
  -> Faithfulness Check
  -> SSE / JSON 返回
```

### Agent 工作流

```text
Planner Agent
  -> 判断问题类型、需要的知识范围、是否需要工具

Retriever Agent
  -> 多路召回文档片段、历史问答、业务术语

Reranker
  -> 二次筛选有效上下文

Answer Agent
  -> 生成带引用的回答

Verifier Agent
  -> 检查回答是否基于上下文，是否存在幻觉

Repair Agent
  -> 如果验证失败，重新检索或要求澄清
```

## 数据模型草案

### 文档表

```sql
CREATE TABLE documents (
  id UUID PRIMARY KEY,
  tenant_id UUID NOT NULL,
  title TEXT NOT NULL,
  file_name TEXT,
  file_type TEXT,
  source_type TEXT NOT NULL,
  status TEXT NOT NULL,
  metadata JSONB DEFAULT '{}',
  created_at TIMESTAMP NOT NULL,
  updated_at TIMESTAMP NOT NULL
);
```

### 分块表

```sql
CREATE TABLE document_chunks (
  id UUID PRIMARY KEY,
  document_id UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  tenant_id UUID NOT NULL,
  chunk_index INT NOT NULL,
  parent_chunk_id UUID,
  content TEXT NOT NULL,
  summary TEXT,
  token_count INT,
  metadata JSONB DEFAULT '{}',
  embedding VECTOR(1536),
  search_vector TSVECTOR,
  created_at TIMESTAMP NOT NULL
);
```

### 会话表

```sql
CREATE TABLE conversations (
  id UUID PRIMARY KEY,
  tenant_id UUID NOT NULL,
  user_id UUID NOT NULL,
  title TEXT,
  created_at TIMESTAMP NOT NULL,
  updated_at TIMESTAMP NOT NULL
);
```

### 消息表

```sql
CREATE TABLE messages (
  id UUID PRIMARY KEY,
  conversation_id UUID NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
  role TEXT NOT NULL,
  content TEXT NOT NULL,
  metadata JSONB DEFAULT '{}',
  created_at TIMESTAMP NOT NULL
);
```

### Trace 表

```sql
CREATE TABLE rag_traces (
  id UUID PRIMARY KEY,
  conversation_id UUID,
  message_id UUID,
  query TEXT NOT NULL,
  rewritten_queries JSONB,
  retrieved_chunks JSONB,
  reranked_chunks JSONB,
  final_context JSONB,
  model_name TEXT,
  token_usage JSONB,
  latency_ms INT,
  created_at TIMESTAMP NOT NULL
);
```

### 评测表

```sql
CREATE TABLE eval_cases (
  id UUID PRIMARY KEY,
  tenant_id UUID NOT NULL,
  question TEXT NOT NULL,
  expected_answer TEXT,
  expected_sources JSONB,
  tags TEXT[],
  difficulty TEXT,
  created_at TIMESTAMP NOT NULL
);

CREATE TABLE eval_runs (
  id UUID PRIMARY KEY,
  case_id UUID NOT NULL REFERENCES eval_cases(id),
  generated_answer TEXT,
  retrieved_chunks JSONB,
  metrics JSONB,
  passed BOOLEAN,
  created_at TIMESTAMP NOT NULL
);
```

## 阶段计划

### 阶段 1：基础 RAG 后端

目标：完成一个可运行的文档问答后端。

交付：

- 文档上传
- 文档解析
- 文档分块
- Embedding 入库
- pgvector 检索
- 基础问答
- 引用来源返回

技术亮点：

- PostgreSQL + pgvector
- Metadata-aware Chunking
- OpenAI-compatible LLM Gateway

验收标准：

- 可上传 Markdown/TXT/PDF/DOCX。
- 可对文档提问。
- 回答中返回引用片段。

### 阶段 2：进阶检索

目标：从简单向量检索升级为 Hybrid Retrieval。

交付：

- PostgreSQL FTS 关键词检索
- 向量检索
- Metadata Filter
- 多查询改写
- 结果融合
- Rerank
- Context Builder

技术亮点：

- Hybrid Search
- Query Rewrite
- Rerank
- Token Budget 控制

验收标准：

- 每次问答能看到检索 trace。
- 可比较向量检索、关键词检索、混合检索结果。
- 能解释最终上下文如何选择。

### 阶段 3：Agentic RAG

目标：让系统从“检索后回答”升级为“规划、检索、验证、修复”。

交付：

- Planner Agent
- Retriever Agent
- Answer Agent
- Verifier Agent
- Repair Agent
- Agent 状态机

技术亮点：

- LangGraph 或自研 Workflow
- Agent 状态流转
- Tool Calling
- 失败回退与澄清机制

验收标准：

- 对复杂问题能拆解检索计划。
- 回答前能做依据检查。
- 上下文不足时能要求澄清。

### 阶段 4：评测与可观测性

目标：让项目具备工程可信度。

交付：

- Trace 日志
- Prompt 日志
- 检索结果日志
- Token 和耗时统计
- 评测用例管理
- 批量评测
- 指标看板

技术亮点：

- OpenTelemetry 思路
- RAG Evals
- 回归测试
- 质量指标可量化

验收标准：

- 每次问答可查看完整链路。
- 每次改动后可运行评测集。
- 能对比优化前后效果。

### 阶段 5：安全与企业级能力

目标：补齐真实企业落地需要的能力。

交付：

- 租户隔离
- 用户权限
- 文档 ACL
- Prompt Injection 防护
- PII 脱敏
- 限流
- Docker Compose 部署
- CI/CD

技术亮点：

- 多租户 RAG
- 安全 RAG
- 后端工程化交付

验收标准：

- 不同租户只能检索自己的文档。
- 敏感信息可脱敏。
- 恶意提示词不能绕过权限和系统约束。

为了快速进入实现，第一版建议：

- 多语言后端
