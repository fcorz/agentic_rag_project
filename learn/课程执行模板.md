# 课程执行模板

每一课建议按下面格式执行和记录。

## 1. 项目案例导读

记录本课对应的项目文件：

```text
源码文件：
- ...

数据库文件：
- ...

接口或命令：
- ...
```

需要回答：

- 这个模块解决什么问题？
- 输入是什么？
- 输出是什么？
- 它和上下游模块如何连接？
- 当前实现有什么优点和限制？

## 2. 自己编写 demo 验证

demo 只验证一个核心知识点，不追求完整系统。

建议记录：

```text
demo 名称：
运行命令：
输入样例：
输出样例：
验证结论：
```

demo 原则：

- 能独立运行。
- 输入输出清晰。
- 尽量少依赖主项目。
- 写完后能用一句话解释它验证了什么。

## 3. 学习总结

建议写入每课目录下的 `summary.md`：

```markdown
# 学习总结

## 本课掌握

## 当前项目实现

## 我的 demo 验证

## 关键源码位置

## 不足与改造方向

## 可用于分享的表达
```

## 4. 验收标准

每课结束前确认：

- 能画出本课模块在 RAG 链路中的位置。
- 能说清本课技术点解决的问题。
- 能运行本课 demo。
- 能指出当前项目实现的不足。
- 能提出一个合理增强方案。
