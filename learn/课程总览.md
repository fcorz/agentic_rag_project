# 课程总览

这套课程围绕当前 Agentic RAG 项目展开，共 16 课时。课程顺序按照真实系统链路设计：先跑通项目，再拆文档入库，再拆检索，再拆 Agent，最后补齐评测、安全和部署。

## 阶段一：项目全景与服务基础

### 第 01 课：项目启动与系统全景

目标：建立对项目结构、运行方式、完整链路的整体认识。

项目导读：

- `README.md`
- `docker-compose.yml`
- `agent/api.py`
- `ingestion/ingest.py`
- `sql/schema.sql`

demo 验证：

- 画出从 PDF 入库到用户问答的调用链路图。
- 用 curl 分别调用 `/health`、`/documents`、`/chat/stream`。

总结重点：

- API、UI、PostgreSQL 三个服务如何协作。
- 文档入库链路和问答链路分别经过哪些模块。

### 第 02 课：FastAPI、配置与服务边界

目标：掌握 FastAPI 生命周期、环境变量、Docker 内外网络差异和 SSE 基础。

项目导读：

- `agent/api.py`
- `ui/app.py`
- `agent/models.py`
- `docker-compose.yml`
- `.env`

demo 验证：

- 写一个最小 FastAPI 服务，包含 `/health` 和 `/stream`。
- 写一个最小 Streamlit 页面，请求 FastAPI SSE 接口。

总结重点：

- `localhost` 和 Docker service name 的区别。
- API 容器、UI 容器、浏览器三者访问地址不同。
- SSE 事件如何从后端流到前端。

### 第 03 课：数据模型与 pgvector 底座

目标：理解 RAG 系统的数据表、索引、向量字段和数据库函数。

项目导读：

- `sql/schema.sql`
- `agent/db_utils.py`

demo 验证：

- 建一个最小 `documents/chunks` 表。
- 插入几条手工向量。
- 用 pgvector 查询最相似记录。

总结重点：

- 为什么 chunk 要单独建表。
- `embedding vector(1536)` 的含义。
- GIN、ivfflat、FTS 索引分别解决什么问题。

## 阶段二：文档入库链路

### 第 04 课：文档解析

目标：掌握 PDF 到 Markdown 文本的转换，并理解其他格式的扩展方式。

项目导读：

- `ingestion/extract_files.py`
- `ingestion/ingest.py`

demo 验证：

- 用 Docling 解析一个 PDF。
- 输出 Markdown 文本和 metadata。
- 比较开启和关闭 table/image 解析的差异。

总结重点：

- 非结构化文档如何进入 RAG 系统。
- 表格、图片、页码、标题等 metadata 为什么重要。

### 第 05 课：分块策略

目标：掌握 recursive chunking、semantic chunking，并理解 parent-child chunking 的设计意义。

项目导读：

- `ingestion/chunker.py`
- `agent/models.py` 中的 `IngestionConfig`

demo 验证：

- 手写一个递归字符分块 demo。
- 使用当前项目 chunker 对同一文本设置不同 chunk size。
- 观察 chunk 数量、重叠内容和语义完整性。

总结重点：

- chunk size 和 overlap 如何影响召回。
- semantic chunking 的成本和收益。
- parent-child chunking 适合解决什么问题。

### 第 06 课：Embedding 流水线

目标：掌握文本向量化、模型配置、批量 embedding 和入库流程。

项目导读：

- `ingestion/ingest.py`
- `agent/tools.py`
- `agent/providers.py`

demo 验证：

- 对 3 段文本生成 embedding。
- 计算两段文本向量的 cosine similarity。
- 将 embedding 写入 PostgreSQL。

总结重点：

- LLM 模型和 embedding 模型是两类能力。
- embedding base_url/key 可以和聊天模型分开配置。
- embedding 维度必须和 pgvector 字段一致。

## 阶段三：检索链路

### 第 07 课：向量检索

目标：掌握 pgvector 相似度搜索和向量召回流程。

项目导读：

- `sql/schema.sql` 的 `match_chunks`
- `agent/db_utils.py` 的 `vector_search`
- `agent/tools.py` 的 `vector_search_tool`

demo 验证：

- 写一个 query embedding -> pgvector search 的最小脚本。
- 调整 limit，观察召回结果。

总结重点：

- cosine distance 和 similarity 的换算。
- 向量检索擅长语义相似，但不擅长精确词匹配。

### 第 08 课：关键词检索

目标：掌握 PostgreSQL FTS，理解 BM25 和关键词召回的价值。

项目导读：

- `sql/schema.sql` 的 `to_tsvector`、`plainto_tsquery`、`ts_rank_cd`
- `idx_chunks_content_trgm`

demo 验证：

- 建一个文本表。
- 使用 `to_tsvector` 和 `plainto_tsquery` 查询关键词。
- 比较关键词检索和向量检索的命中差异。

总结重点：

- 为什么精确术语、编号、人名、产品名更适合关键词检索。
- PostgreSQL FTS 和 BM25 思路的关系。

### 第 09 课：混合检索

目标：掌握 Vector + Keyword 的融合召回和权重排序。

项目导读：

- `sql/schema.sql` 的 `hybrid_search`
- `agent/db_utils.py` 的 `hybrid_search`
- `agent/tools.py` 的 `hybrid_search_tool`

demo 验证：

- 写一个最小 hybrid search SQL。
- 调整 `text_weight`，观察排序变化。
- 记录 3 个不同问题的召回结果。

总结重点：

- 混合检索为什么通常比单一路径稳定。
- 权重、归一化、去重对排序的影响。

## 阶段四：模型调用与 Agent

### 第 10 课：模型调用与 Prompt

目标：掌握 OpenAI-compatible API、Responses API、Prompt Template 和结构化输出思路。

项目导读：

- `agent/providers.py`
- `agent/prompts.py`

demo 验证：

- 写一个最小模型调用 demo。
- 分别测试 `chat` 和 `responses` 模式。
- 写一个要求 JSON 输出的 prompt。

总结重点：

- `OPENAI_BASE_URL`、`OPENAI_API_MODE`、`LLM_CHOICE` 的作用。
- Prompt 如何影响工具调用和回答风格。
- 结构化输出如何降低解析不稳定性。

### 第 11 课：工具调用

目标：掌握 Tool Calling、输入模型、工具注册和结果转换。

项目导读：

- `agent/agent.py`
- `agent/tools.py`
- `agent/models.py` 的 `ToolCall`

demo 验证：

- 给 Agent 注册一个简单计算工具。
- 让模型判断是否调用工具。
- 打印 tool name、args 和返回值。

总结重点：

- 工具 docstring 和参数 schema 为什么重要。
- 工具是 Agent 连接外部系统的标准接口。

### 第 12 课：Agent 工作流

目标：理解当前项目的 Agent 编排方式，并能设计多阶段状态机。

项目导读：

- `agent/agent.py`
- `agent/api.py` 的 `execute_agent`、`chat_stream`
- `agent/db_utils.py` 的会话函数

demo 验证：

- 写一个三阶段伪 Agent：plan -> retrieve -> answer。
- 将每一步状态打印出来。

总结重点：

- 当前项目是 Pydantic AI 工具驱动 Agent。
- LangGraph 或自研状态机适合显式多阶段流程。
- 会话上下文如何影响回答。

## 阶段五：进阶 RAG 能力

### 第 13 课：查询理解与改写

目标：掌握 Query Rewrite、Intent Detection 和 Structured Planning 的基本实现。

项目导读：

- 当前项目中 `execute_agent` 拼接历史上下文的方式。
- `agent/prompts.py`
- `agent/tools.py`

demo 验证：

- 写一个 query rewrite prompt。
- 输入口语问题，输出检索友好问题。
- 判断问题类型：事实查询、总结、比较、无关问题。

总结重点：

- 为什么用户原始问题不总是适合直接检索。
- query rewrite 如何提升召回。
- intent detection 如何决定是否检索、检索哪里、检索多少。

### 第 14 课：Rerank 与上下文构建

目标：掌握二次排序、上下文压缩、引用构建和答案 grounding。

项目导读：

- 当前项目 `hybrid_search_tool` 返回 chunk 后直接交给 Agent。
- `agent/prompts.py`
- `agent/models.py` 的 `ChunkResult`

demo 验证：

- 对 top-10 chunks 实现一个规则 rerank。
- 写一个 LLM rerank prompt。
- 将 top chunks 拼成带来源的 context。

总结重点：

- Rerank 如何减少无效上下文。
- Context Builder 应该控制 token、去重、保留来源。
- Citation Builder 如何让回答可追溯。

## 阶段六：工程闭环

### 第 15 课：评测与可观测性

目标：掌握 Golden Set、基础 RAG eval、trace log、prompt log 和 retrieval log。

项目导读：

- `tests/`
- `agent/api.py` 日志
- `agent/db_utils.py` 会话和消息记录

demo 验证：

- 编写 5 条 golden questions。
- 记录检索结果、答案、来源和人工评分。
- 为一次问答生成 trace JSON。

总结重点：

- RAG 不能只靠主观感觉评估。
- 召回质量和回答质量要分开看。
- 可观测性是排查幻觉、慢查询和工具失败的基础。

### 第 16 课：安全与工程交付

目标：掌握权限过滤、Prompt Injection 防护、PII Masking、Docker 部署和工程交付清单。

项目导读：

- `docker-compose.yml`
- `Dockerfile`
- `docs/Docker部署.md`
- `docs/线上单机服务部署.md`
- `agent/models.py`

demo 验证：

- 给文档 metadata 加 tenant_id，并在检索时过滤。
- 写一个 prompt injection 检测 demo。
- 写一个 PII masking demo。
- 整理一份上线检查清单。

总结重点：

- 企业知识库必须先做权限过滤，再做检索。
- Prompt Injection 防护要覆盖文档内容和用户输入。
- 工程交付要保证可部署、可复现、可观测、可回滚。
